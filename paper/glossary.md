# Glossary

One definition per term. Chapter in brackets is where the term is defined formally. Notation is in [notation.md](notation.md).

## Direction (four distinct terms, finding 10)

The unqualified word "direction" is not used in the paper.

- **Edge orientation**: the source-to-target orientation of a relationship. Stored in the relationship state. [Ch. 3]
- **Traversal direction**: which orientation a pattern or scan follows from an endpoint: outgoing, incoming or either. A property of a query, not of data. [Ch. 11 for scans, Ch. 5 for patterns]
- **Sync direction**: the direction in which changes of a projection may propagate: forward (input to output), backward (output edits mapped to input edits) or both. Declared per rule. A projection need not be bidirectional. [Ch. 8]
- **Flow direction**: the direction of network traffic observed by a source (client to server, ingress, egress). Source data. [Ch. 10]

## Terms
- **Abstraction highlight**: in the canvas, the marking of what a selected element stands for at the levels below and what it is part of at the levels above, found by following lineage in both directions. [Ch. 12]
- **Adapter**: compiled engine code that turns the native records of one source into typed rows and coverage controls. It resolves no identity and creates no facts. [Ch. 10]
- **Aggregate (of a window)**: the value of a monoid computed over the samples of one window, fixed by the series kind. [Ch. 7]
- **Allocation (entity id)**: derivation of an entity id from the canonical bytes of an identity key. A pure function. [Ch. 1]
- **Apply**: partial function from a patch and a graph to a graph, defined iff every edit's before state matches. [Ch. 4]
- **As-if value**: the value a telemetry window of the survivor of an identity merge would hold if every sample had been written under the survivor from the start. [Ch. 7, Law 7.5]
- **Authored partition**: the part of the master graph written only from rows of the internal `sattle.authoring` source. Backward edits end here. [Ch. 8]
- **Backward edit**: proposed patch on a derived graph, with base revisions along its path, mapped to the source by `put`. [Ch. 8]
- **Batch-invariance premises**: B1 one writer per telemetry key, B2 late rows are a function of logical time, B3 identity binding independent of arrival order. Premises of Theorem 6.2. [Ch. 6] A fourth, B4, was found by deriving the proof again: within a step, advances and structure changes take effect on carried threshold state in recorded order.
- **Bijective rule**: rule with an inverse that satisfies GetPut, PutGet and PutPut. [Ch. 8]
- **Binding (identity)**: immutable record mapping a canonical identity key to an entity id. [Ch. 1]
- **Binding set**: the append-only set of bindings of a tenant, built by allocate, alias and migrate. [Ch. 1]
- **Block (document)**: unit of a document with an id derived from rule id and group key, never from position. [Ch. 12]
- **Bounded reach**: the pairs joined by at most `D` `Affects` edges, computed by `Traverse` to depth `D`. The health model uses `D = 16`. [Ch. 7, Prop. 7.8]
- **Canonical definition graph**: a definition graph that is the result of parsing a text; the graphs on which printing and parsing are inverse under premise RT. [Ch. 5, Theorem 5.6]
- **Canonical encoding**: `enc(v)`, see Canonical form. [Ch. 1]
- **Canonical form**: the unique byte string `enc(v)` of a value or state under RFC 8785 plus the normalization rules. [Ch. 1]
- **Canonical key bytes**: JCS serialization of tenant, domain name and the encoded components of an identity key. [Ch. 1]
- **Canonicalization version**: name of the rule set that produces canonical bytes. Recorded with a binding, not part of an identity key. [Ch. 1]
- **Canvas**: the graph viewer. A subscriber of graph feeds, consuming them through the `GraphSource` seam. [Ch. 12]
- **Carry policy**: per-projection choice (keep or drop) for elements whose creating inputs were evicted when the projection is edited. [Ch. 9]
- **Catalog**: the per-tenant graph holding all definitions (modules, releases). [Ch. 2]
- **Chunk**: a batch of input rows evaluated and committed together. Its size changes patch granularity and, by Theorem 6.2, not the result. [Ch. 6]
- **Closed window**: a window whose aggregate has been fixed by a logical-time input and recorded as an input. [Ch. 7]
- **Closure (ontology)**: a module's declarations plus those of its transitive imports at the pinned releases. [Ch. 2]
- **Commit record**: the durable record of one revision: its patch, frontier and cause. [Ch. 3]
- **Commit rule**: condition for committing an edit set at the head: non-empty, effective, guards hold, result well-formed. [Ch. 3] It enforces the guards and WF1 to WF3; an element that misses a required property after a counted fault or a reported conflict is committed and reported (Theorem 5.2).
- **Compatibility class**: classification of an ontology change as compatible or breaking for readers and for writers. [Ch. 2]
- **Complement (lens)**: the part of the source that a view omits. For a stored source it is the pinned source revision. [Ch. 8]
- **Component**: an element of the health model (workload, service, node, cluster, load balancer, network, Event Hubs namespace) that has a health state. [Ch. 7]
- **Composition (`then`)**: partial operation on patches, defined iff the revisions are adjacent and the guards agree. [Ch. 4]
- **Configuration edit by full replay**: the engine's realization of a configuration edit. It replays the whole retained input log through the new definitions on a fresh engine and commits the final difference per graph. [Ch. 9]
- **Conformance**: relation `G ⊨ Σ` of a graph to an ontology closure. [Ch. 2]
- **Content tag**: the `ETag` of every cached response, the first 32 hexadecimal digits of SHA-256 over the media type, a newline and the body; equal bytes have equal tags in any run. [Ch. 12, Prop. 12.10]
- **Contribution**: the fragments one source record causes, identified by a stable contribution key. [Ch. 9, 10]
- **Cosmos store**: the storage port on Cosmos DB for NoSQL with five containers and hierarchical partition keys. Built against the vNext emulator. [Ch. 11, 11.12]
- **Coverage**: an adapter's declaration that a scan enumerated every record of a scope at a consistency level. Source of authoritative absence. [Ch. 10]
- **Crossing operator**: the path `Series`, `Rollup`, `Delta`, `Threshold` that reads closed windows of telemetry and emits graph data. The only way telemetry influences structure. [Ch. 5, 7]
- **Dangling relationship**: relationship whose source or target entity is not present in the graph (ADR-084). [Ch. 3] Its missing endpoint is a **reference** (see there).
- **Delivery key**: stable key of a source record. A re-delivery has the same key. [Ch. 10]
- **Delta (signed)**: finite-support map from facts to integers; element of the group `ℤ^(F)`. [Ch. 4]
- **Derived graph**: output graph of a projection, a graph in the graph space other than the master. [Ch. 3]
- **Derived view**: informal name for a derived graph or document shown to a user. [Ch. 0]
- **Digest**: `sha256:` plus the hex SHA-256 of a canonical encoding. [Ch. 1]
- **Document (projection)**: an ordered list of blocks derived from graph facts, with its own revision, source revision vector and completeness flag (model of Def. 12.5). The engine realizes it as a document graph, without the vector and the flag. [Ch. 12]
- **Document graph**: a derived graph whose output ontology is `sattle.doc`: `Block` entities rendered by one generic renderer to deterministic Markdown with a digest per revision. [Ch. 12, Def. 12.8]
- **Document patch**: block edits plus before and after block order, applied against an exact base. [Ch. 12]
- **Draft**: an overlay on the catalog graph at a base revision, built from guarded patches. It creates no catalog revision until it is committed. [Ch. 4]
- **Edit**: replacement of one element's state, with its expected before state. [Ch. 4]
- **Edit replay**: the designed handling of a configuration edit: previous graph first, retained inputs replayed, one net patch. The prototype does a full replay on a fresh engine instead. [Ch. 9]
- **Effective edit**: edit whose before and after states differ. [Ch. 3]
- **Element key**: key of an entity, a relationship or the ontology slot of one graph. [Ch. 3]
- **Embedding (`χ`)**: map from a graph to its signed delta of facts. [Ch. 4]
- **Entity / entity id**: node of a graph and its timeless identifier. [Ch. 1, 3]
- **Envelope**: capture or transport wrapper of a native record with source, receipt time, sequence, key and context. [Ch. 10]
- **Estate**: the set of cloud resources, clusters and workloads under analysis. [Ch. 0]
- **Event stream (protocol version 3)**: the one ordered stream of server events, each with a server-wide sequence number, that a client folds into local state and resumes with `after`. [Ch. 12]
- **Evidence (element history)**: the last `N` inputs that changed an element, per projection. A derived index of the log. [Ch. 9]
- **Evidence class (A to E)**: level of support of a claim in Ch. 14: proof, seeded property test, fixture test, benchmark, replay of the real capture. [Ch. 14]
- **Evidence element**: a graph element that stands for one observed event (an Activity Log operation, an audit request, a Kubernetes warning) with an edge to what it concerns. Not the evidence history. In the prototype it is retained for 24 hours of logical time by the `Retain` operator. [Ch. 9, 9.6]
- **Extension (ontology)**: a module's addition of properties to an imported type. [Ch. 2]
- **Fact**: an element state under its key, in canonical form. Unit of signed deltas. [Ch. 4]
- **Fibre** (of a lifted edge): the edges of the graph below that have the same pair of images and that the lifted edge stands for. [Ch. 5, Def. 5.17]
- **Flow log tuple**: one comma separated record of a VNet flow log with 13 fields, among them event time, addresses, ports, protocol, direction and the flow state `B`, `C`, `E` or `D`. [Ch. 10]
- **Forwarder**: the lab process that publishes capture envelopes and its own loss and restart markers to an Event Hub. [Ch. 10]
- **Forwarder marker**: a record of source `sattle-forwarder` (`start`, `stop`, `relist-start`, `relist-end`, `dropped`, `hubble-reconnect`, `watch-expired`, `watch-error`, `poll-failed`). The engine consumes five of them. [Ch. 10, 10.6]
- **Frontier**: the positions consumed by a commit: source positions, input graph revisions and configuration revision. Evidence of dependencies, not a consistent cut. [Ch. 3]
- **Gate**: a condition of the research plan that is closed by named evidence and not by code that exists. Phase 1 has the gates 1a (theory), 1b (flexible and expressive) and 1c (efficient); Phase 2 has 2a (a health model from real Azure data), 2b (human understandable) and 2c (always live). [README, Ch. 0]
- **Graph**: finite partial map from element keys to element states, satisfying the uniqueness invariant. Scoped by tenant and graph id. [Ch. 3]
- **Graph data**: properties with role GraphData. Part of graph equality, revisions and patches. [Ch. 3]
- **Graph equality**: equality of key sets and of states up to value equality. Compares graph data only. [Ch. 3]
- **Graph feed**: sealed snapshot followed by adjacent commit records, plus a separate telemetry feed. [Ch. 12]
- **Graph space**: acyclic set of graphs with one master graph and derived graphs reachable from it. [Ch. 3]
- **Group commit**: committing several consecutive revisions in one store batch, with revision boundaries preserved. [Ch. 11]
- **Guard**: the before state of an edit, which must match the graph for `apply` to be defined. Guard identity: the patch of guard-only edits of a patch. [Ch. 3, 4]
- **Health state**: `Healthy`, `Degraded`, `Unhealthy` or `Unknown` of a component, the worst own severity over everything that affects it. `Unknown` means no data. [Ch. 7]
- **Hot graph**: in-memory copy of one graph that the engine evaluates against. A cache of the log, not a source of truth. [Ch. 11]
- **Hub bucket**: one of `B` partitions over which the adjacency list of a high-degree entity is spread. [Ch. 11]
- **Hypothesis (performance)**: target with a named benchmark and a refutation rule; it gets a status only from measurements (Def. 13.5). [Ch. 13]
- **Hysteresis**: entry and exit thresholds plus a minimum run length that bound how often a crossing operator toggles. [Ch. 7]
- **Identity domain**: namespace that fixes the components and kinds of an identity key. [Ch. 1]
- **Identity key**: tenant, domain and component tuple identifying an entity. [Ch. 1]
- **Identity merge**: the additive forwarding record from the larger to the smaller identity when late evidence says two keys denote one entity. Bindings are never modified; `Rep` follows the chain. [Ch. 1, Theorem 1.7]
- **Image** (of a level): the partial function from the nodes of the graph below to the nodes of a level; a node outside its domain has no image. It is data: a relationship or a computed key. [Ch. 5, Def. 5.16]
- **Immutable resource**: a protocol resource addressed by revision or digest that never changes for fixed arguments and so is cached without revalidation. [Ch. 12]
- **Index set**: the per-element items a store keeps for reads: versions, adjacency, uniqueness, evidence. [Ch. 11]
- **Information class (`δ`)**: iso, lens or none, how much of its input an operator or rule preserves. [Ch. 8]
- **Ingestion sequence**: engine-assigned total order of durably accepted inputs. [Ch. 3]
- **Input**: any item accepted by the engine: native batch, graph change, logical-time control, closed-window record. [Ch. 3]
- **Inverse (patch)**: patch with `from`/`to` and every before/after state swapped. Not committed, an undo is a new forward revision. [Ch. 4]
- **Journal** (of a space): the ordered sequence of everything that entered a served space (input batches, logical-time advances, losses, definition commits, an end marker, and for a live input its envelopes with source positions and its flushes), kept in the store next to the commit log; a restart replays it (after the latest usable state seal, if there is one) and compares every recomputed commit with the stored one. [Ch. 11, 11.7]
- **Kernel**: the closed, compiled meta-ontology of definition graphs, and the engine's only compiled vocabulary besides operators and functions. [Ch. 2]
- **Kind (telemetry)**: gauge, counter, windowSum or distribution. Fixes how samples roll up. [Ch. 7]
- **Late horizon**: the number of window widths (3 for a live source, a million for a recorded capture whether replayed or served, unless `--late-horizon` is given) for which a closed window stays revisable before its state is dropped. Not part of Def. 7.6; a later row for such a window is dropped and counted. [Ch. 7]
- **Late policy**: allowed lateness and action (drop or amend) for samples that arrive after their window closed. [Ch. 7]
- **Lens**: pair `get`, `put` with laws GetPut, PutGet and optionally PutPut. [Ch. 8]
- **Level**: a graph that abstracts the graph below it: nodes below map to their images, and edges below are lifted to edges between images. Written with the `lift` statement. [Ch. 5, 5.8]
- **Lift (statement, operator kind)**: one statement per level that lifts the edges of a lower graph along a mapping to edges between images, with clauses for carried, derived and state properties and for a node with several images. An operator kind of the kernel that the planner lowers to existing operators. [Ch. 5, 5.8]
- **Lifted edge**: the one edge between two images that stands for all edges below with that pair of images. Self-loops and edges with an end that has no image are not lifted; counters are summed over the fibre, ratios and states are computed again. [Ch. 5, Def. 5.17, 5.18]
- **Lineage**: the set of input ids a fact owes its presence to. [Ch. 9]
- **Live input**: a reader of an Event Hub whose events are capture envelopes. Logical time comes from the recorded `capturedAt`. [Ch. 10]
- **Live resume**: a live input started on a store that has a journal continues its source after the position journaled with the last envelope it consumed, and drops an envelope delivered again by its delivery key. [Ch. 10, Def. 10.8]
- **Logical partition**: set of store items sharing one full partition key value, the unit of atomic batches. [Ch. 11]
- **Logical time**: time that advances only through explicit inputs. [Ch. 3]
- **Master graph**: the unique graph fed by ingestion; source vertex of the graph space. [Ch. 3]
- **Materialization (delta)**: reading a signed delta as a graph state, defined iff weights are 0 or 1 and the invariant holds. [Ch. 4]
- **Materialization (store)**: writing a committed patch into the version index. [Ch. 11]
- **Metric (performance)**: a measured quantity with a unit, M1 to M12. [Ch. 13]
- **Migration**: projection that moves a graph from one ontology release to another with an ontology edit. [Ch. 2]
- **Module, release**: unit of definition and import; a sealed, digested version of a module. [Ch. 2]
- **Native record**: a source's own format of a change or observation. [Ch. 0]
- **Net patch**: patch with guard-only edits removed. Lossy. [Ch. 4]
- **Observation**: a native record interpreted by an adapter. Evidence, not fact. [Ch. 0]
- **Observed time**: time at which a source says a sample or event occurred. Valid time, never an index of graph revisions. [Ch. 3]
- **Ontology**: versioned type vocabulary, a module of the catalog graph, typed by the kernel. Graphs conform to its closure. [Ch. 2]
- **Operator kernel**: the closed set of 20 operator kinds with fixed port signatures. [Ch. 5]
- **Output union**: the multiset of all element facts and telemetry windows of all graphs of a space with the graph name forgotten. A refactoring keeps it. [Ch. 5]
- **Ownership (rule)**: at most one rule of an editable class sets a given entity type property or emits a given relationship type. [Ch. 5]
- **Palette**: the description of every operator, rule class, aggregate and function the editor can place, derived from the kernel table and the engine's support list. [Ch. 12]
- **Parameter (projection)**: an input port of kind `param` with a value kind and an optional default. A constant in the projection, bound to a literal by the graph space. [Ch. 5, Def. 5.14]
- **Partition key**: hierarchical key that places an item in a logical partition. [Ch. 11]
- **Patch**: guarded set of edits from one revision to another. [Ch. 4]
- **Plane**: structural plane (graph data, revisioned) or telemetry plane (series, not revisioned) of one graph. [Ch. 3, 7]
- **Port, port mode, wire**: typed connection point of an operator or projection (mode in or out, kind rows or graph) and the edge between two ports. The port mode is not a direction in the glossary sense. [Ch. 5]
- **Premise (named)**: a property that a proof uses and the model does not give: of the engine, of one of its programs, or of an external system. It has a name (KS, RT, R0 to R5, B1 to B4, J1 to J3, SL1, LV, LR, KW) and a test, existing or wanted. A statement that uses one is "proved under premises". [inventory]
- **Preview**: evaluation of a draft on a fresh engine over a stated number of retained input rows, without committing or touching the live engine. [Ch. 9]
- **Projection**: the definition of a transformation, a typed graph in the catalog. Never the output. The output is a derived graph. [Ch. 3, 5]
- **Property role**: GraphData or Telemetry, declared by the ontology per property. [Ch. 3, 7]
- **Provenance semiring**: commutative semiring in which positive operators are evaluated to carry support, lineage or weights. [Ch. 9]
- **Rebuild**: edit of a graph-input projection by evaluating the new definition on the pinned input graphs. [Ch. 9]
- **Reconciliation policy**: rule that withdraws a source's contribution for elements of a scope absent from a complete scan. [Ch. 10]
- **Refactoring**: extract, inline or move rule, a pure function on projection text that returns a draft patch and keeps the output union. [Ch. 5]
- **Reference** (of a graph): an entity id that a relationship of the graph names as an endpoint and that the graph does not hold; `inOtherGraph` or `absent`, with the identity key the id was minted from. [Ch. 3, Def. 3.14]
- **Reference machine (ten-run figures)**: by project decision the lab laptop when no other session runs. The Azure reference of Def. 13.4 remains the target for Cosmos figures. [Ch. 13]
- **Reference stub**: in the canvas, the drawing of a reference: a hollow node with a dashed outline for an endpoint that the graph does not hold, with the reason. [Ch. 12]
- **Relationship**: directed typed edge between two entity ids, with its own id. [Ch. 3]
- **Release**: a module version identified by its digest, created by a committed catalog revision that changes the module. It can be listed, diffed and restored. [Ch. 9]
- **Replica**: consumer-side copy of a graph built from a snapshot and guarded patches. [Ch. 12]
- **Retain** (operator): `retain on time for 24h`; a row passes unchanged and is withdrawn (the same row with weight minus one) when the logical frontier reaches its time plus the age, so what is derived only from it is retracted by the support counts. [Ch. 5, Def. 5.15]
- **Retained set**: ordered union of the element histories of a projection, each input once. [Ch. 9]
- **Revision**: position in the per-graph totally ordered commit log. [Ch. 3]
- **Revision log**: the chain of commit records of one graph. [Ch. 3]
- **Ring (telemetry)**: in-process compressed buffer of recent samples per series. [Ch. 11]
- **Role non-interference**: graph data depends on data-role fields and threshold outputs only. [Ch. 5]
- **Runtime fault**: an evaluation without a value (division by zero, overflow, a failing canonicalizer, a missing required column). It is local to its row: the value is absent, the fault is counted, the event does not fail. [Ch. 5, Def. 5.19]
- **Row contract (`RowType`)**: typed shape of the rows an adapter delivers. [Ch. 2, 10]
- **Rule (projection)**: group of sinks with a sync class. [Ch. 5, 8]
- **Scoped graph**: graph whose id is derived from a source graph and a canonical scope. [Ch. 3]
- **Seal**: record binding the pages, descriptor, digest and frontier of a snapshot. [Ch. 11] Not built; see **State seal**.
- **Seam (`GraphSource`)**: the consumer contract between engine and canvas: open, snapshot, subscribe, telemetry, correspondences, evaluate. [Ch. 12]
- **Series (telemetry)**: time-indexed samples of one telemetry property of one element. [Ch. 7]
- **Series declaration**: ontology-side record of kind, value kind, unit, widths, bounds, late policy and retention of a telemetry property. [Ch. 7]
- **Served history**: the patches per graph and the events of the ordered stream that the host keeps in memory to answer `/patches`, older revisions and a resuming subscriber; the last 2,000 patches per graph and the last 20,000 events by default, older requests answer `410 Gap` or `gap`. Not the store's log. [Ch. 11, D30; Ch. 12, Def. 12.7]
- **Signal**: an entity of the health model that holds a measured series of a component and two threshold states, degraded and unhealthy. [Ch. 7]
- **Signed delta**: see Delta (signed). [Ch. 4]
- **Snapshot**: the pages of one graph state at one revision plus its seal. [Ch. 11]
- **Source**: external system that emits native records. [Ch. 0]
- **Squash**: net form of a composed batch of patches, with a loss report. [Ch. 4]
- **Staged check**: the evaluation of a proposed backward edit on a copy of the engine, accepted only if the resulting view equals the edited view (PutGet). [Ch. 8]
- **State seal**: a compressed snapshot of the whole state of one engine build after the first `n` journal entries, stored next to the journal; a restart loads the latest usable one and replays only the entries after it. Refused if it was written by another build, if its digests do not match, or if its bytes cannot be read. A restart from it does not recompute the journal before it (`serve --verify-journal` ignores seals and does). Not the page set of the seal above. [Ch. 11, Def. 11.11]
- **Storage port**: engine-internal interface to a store: head, commit, read, scan, follow, seal. A second port serves the telemetry plane. [Ch. 11]
- **Store**: durable implementation behind the storage port. [Ch. 11]
- **Store assumptions**: properties S1 to S5 of a store that the storage theorems rely on. [Ch. 11]
- **Structural plane**: the graph `G_r` restricted to graph data. [Ch. 3]
- **Support**: sum of the weights of the contributions to an element. Present iff positive. [Ch. 9]
- **Supporting element**: an element at the end without value roles of a relationship type whose other end has a property with value roles. The canvas collapses it onto the node it supports. [Ch. 12]
- **Sync class**: forward, readonly, bijective, lens or sync. [Ch. 8]
- **Telemetry**: property data of role Telemetry, stored as series. [Ch. 7]
- **Telemetry frontier**: position in the ingestion order of the last closed-window record applied by a commit. [Ch. 7]
- **Telemetry watermark**: sequence of the last closed-window record of an input graph consumed, part of a frontier entry. [Ch. 6]
- **Tenant**: isolation scope of all ids and data. [Ch. 1]
- **Throughput unit**: the capacity unit of an Event Hubs namespace. One unit is nominally 1 MB/s in; the lab forwarder delivered about 125 events/s per unit. [Ch. 10]
- **Tier (performance)**: workload scale factor with reference hardware and a target table. [Ch. 13]
- **Time alignment (`rev_of`)**: map from observed time to the last revision whose logical time is not later. [Ch. 12]
- **Timeless identity**: invariance of the binding from key to entity id under state, type, ontology and time. [Ch. 1]
- **Type system (judgments)**: the expression, operator, wire, projection and space judgments that every definition satisfies at load. [Ch. 5]
- **Undo**: the application of the inverse of an earlier patch as a new patch. It never removes log entries and is guarded like any patch. [Ch. 4]
- **Uniqueness invariant**: at most one relationship per `(source, target, type)` in a graph. [Ch. 3]
- **Unrolling (fixpoint)**: the engine's `Fixpoint`: `max` copies of the step with `distinct(R union step(R))` between them. Facts that need more steps are not derived. [Ch. 6, D11]
- **Value**: element of the closed tagged union of graph values. [Ch. 1]
- **Value equality**: equality of normalized values, `v ≈ w`. [Ch. 1]
- **Value role**: a presentation hint stored on a property type for one value: `ok`, `warning`, `danger`, `unknown` or `neutral`. Ontology data that the engine serves and does not read. A viewer maps it to a color and a glyph. [Ch. 2, Def. 2.13; Ch. 12]
- **Version row**: a state of one element with the half-open revision interval in which it holds. [Ch. 11]
- **View (element)**: structure at a revision joined with series over a time range. [Ch. 7]
- **Watermark (store)**: highest revision fully materialized into the version index. [Ch. 11]
- **Well-formed graph**: a graph satisfying finiteness, canonical property maps, the uniqueness invariant and conformance to its ontology. [Ch. 3]
- **Window**: half-open aligned interval of observed time over which samples are aggregated. [Ch. 7]
- **Work budget**: deterministic limit on the work of one read. [Ch. 11]
- **Workload model**: estate size, source rates, series count, change fraction and stack depth that a benchmark assumes. [Ch. 13]
