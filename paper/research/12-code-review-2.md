# Research note 12: second code review (13 November)

## In ten lines
1. Reviewed: everything committed on main after the first review, 34 commits (engine, KQL front end, canvas, lab, paper). About 150 suspected defects came up. 107 are confirmed by a test that fails today or by a run, 3 are plausible, 2 were refuted; about 20 more (lab, paper, removed behaviour, a canvas contract) were found by reading and not run.
2. Two inputs kill the engine process: a definition text with about 600 nested brackets sent to the server, and a projection in KQL whose `let` reads a table of its own name. An editor can produce both.
3. Restart from a seal (the snapshot of the engine state the host keeps beside its journal, so a restart need not replay everything) can come back wrong. After a definition commit, the restarted projections can filter on the wrong text. A live space restarted from a seal loses every graph at its next definition commit. The restart tests pass even when no seal is used at all.
4. The health model of the workload counts the answer of a call as a call back. On the real captures half of the pod pairs exist only as answers, so a service with a problem also makes the services it calls look unhealthy.
5. `sattle serve CAPTURE --write-definitions` writes the capture's workload arguments into the tracked definition files. This repository is public.
6. The canvas editors lose an author's work: a commit can leave out edits still on their way, two quick edits make the engine refuse the second, and a new child after a removal collides with an existing one.
7. The KQL front end disagrees with Kusto in ways the note on languages does not list. A missing text counts as "null" where Kusto has an empty text, which the master projection relies on today. `arg_max` mixes columns of different rows. A `union` of two identity kinds mints both in the first. A path of two or more steps measures the shortest distance. Twelve valid KQL texts are accepted and then refused with a line of generated text in another file.
8. The new engine core (the tables behind the sinks) is sound in its main logic. A decimal with another number of digits (2.5 and 2.50) no longer cancels its own insertion. A node with thousands of edges makes every new edge cost time in proportion to all its edges (8,000 edges: 5 s instead of 0.03 s).
9. Merged identities, fill and no data are mostly right. Several latent gaps remain: changes of a merge reach derived graphs one step late, a roll-up after a select puts a whole group in no data when one member is silent, and windows of 3 hours or wider drop every row in a replay.
10. No identifying value of the lab (subscription, tenant, names, addresses, tokens) is in the tracked tree or anywhere in the history of main. The design rules of the repository are best served by one explicit state machine each for the host's restart path and for the canvas editor flow; both would remove confirmed defects.

## Words used here
- Seal: the snapshot of the engine state that a durable host stores beside its journal (the log of every input and commit), so a restart reads the snapshot and replays only the journal after it.
- Interner: the table that gives every text a number; compiled projections hold these numbers, not the texts.
- Sink: the operator that writes elements of a projection's output graph (`emit` in today's text, `nodes` and `edges` in KQL). A fragment is what one sink says about one element.
- Look-back: how far back a series or threshold reads telemetry windows. Time to live: how long an element may stay silent before it is in no data.
- Estate: the synthetic test data in `engine/tests/Sattle.Tests/fixtures/estate`. Latent: no shipped definition or fixture reaches it today, ordinary input would.
- Reached: shipped definitions, the estate, the real captures or ordinary use trigger it today.

## Defects, most severe first
Severity: high = wrong state, lost work, a crash or a leak that ordinary use reaches today; medium = wrong result on plausible input, or a guard that cannot fail; low = an edge, a message, or cost only.

### High

1. **One request or one text kills the engine process.**
   - The parser of the project's own text recurses without a depth limit: an expression with 600 nested brackets, or 450 nested `if(`, overflows the stack (`engine/src/Sattle.Language/Syntax.cs:822`). A stack overflow cannot be caught in .NET; `serve` dies. Any client of `POST /drafts/.../text` or `/check` can send it.
   - The KQL front end: `let pods = pods | where ...` in a projection that reads the table `pods` recurses without end (`engine/src/Sattle.Kql/Lowerer.cs:411-426`). Kusto accepts the text. The front end is meant to parse text as it is typed.
   - Test: `v-host.patch` (runs alone, marked skip because it kills the test host), `v-kql.patch`.

2. **Restart from a seal after a definition commit gives another state.** Compiled plans hold the interner numbers of their text constants. The restore compiles the plans first and loads the sealed interner after, so a constant added by the commit points at another text. The state digest differs from a host that never restarted; without the definition commit the same test passes. `engine/src/Sattle.Runtime/Host.cs:328-335`, `Exprs.cs:93`. Test: `v-seal.patch`.

3. **A live space restored from a seal loses every graph at its next definition commit.** The re-activation reads the inputs back from the journal by the kinds a capture replay writes (`r`, `a`, `g`, `l`); a live run journals `e`, `F`, `L`, `p`. The master went from 79 entities to 0. `Host.cs:339`, `:352-370`. Test: `v-seal.patch`.

4. **The answer of a call counts as a call back** (workload model). Hubble reports the reply of a connection as a flow from the callee to the caller; the adapter ignores `is_reply` and `observedCalls` makes a `Calls` edge for it, so every call gives a dependency in both directions, and a caller with a problem makes the service it calls look unhealthy. `engine/definitions/acme.ops.sattle:119`, `engine/src/Sattle.Runtime/Adapters.cs:344`, `engine/definitions/acme.workload.sattle:153`. Reached on the real captures: `engine/PERF.md:208` measured 118 of 245 pod pairs that exist only as replies. Test: `v-workload.patch`.

5. **`serve CAPTURE --write-definitions` writes the capture's workload into a tracked file.** The capture's space arguments (from `space-arguments.json` beside the fixtures, or the local overlay) are bound into the space; the first definition commit of any module writes every source back, including `engine/definitions/acme.space.sattle`. `engine/src/Sattle.Cli/Program.cs:103`, `:135`, `engine/src/Sattle.Runtime/Host.cs:983`. The first review reported the overlay path; this range adds the arguments file as a second way in. Test: `v-cli.patch` (temporary folders, invented values).

6. **The canvas editors lose work.**
   - Commit goes to the engine before edits still in the session queue: they are left out of the commit (`canvas/src/state/editor-effects.ts:145`).
   - Two edits made quickly are both computed against the same draft; the engine refuses the second (`editor-effects.ts:155`).
   - A new read, list item or unnamed pattern edge takes its id from the child count: after a removal every add collides (`canvas/src/editor/commands.ts:251`). The first review's fix covered constant rows only.
   - Test: `v-canvas.patch`.

7. **A draft becomes unusable with one large number.** A draft patch is applied and recorded before it is checked; an Integer beyond 64 bits, which the canvas's Integer field accepts, answers 500 and every later check, preview and commit of that draft answers 500 too. `engine/src/Sattle.Runtime/Drafts.cs:112`. Test: `v-host.patch`.

### Medium: the KQL front end means something else than Kusto

8. **A missing text is null.** `isnull(name)` is true and `isnotnull(name)` false for an element without `name`, `name != "x"` drops it, `name == ""` finds nothing. In Kusto a text is never null: a missing one is the empty text. On the estate, 2 of 3 services change sides. The master projection and the tree and workload structures rely on presence (15 lines). Not in note 10's list of differences. `Lowerer.cs:1069-1070`. Test: `02-kql-accepted-but-not-loadable.patch` (with the lead's tests).
9. **`arg_max(order, a, b)` takes each column on its own.** On a tie the columns come from different rows, and a missing value in the newest row keeps an older row's value; Kusto returns one row. Reached in `engine/definitions/acme.ops.ingest.kql:30` (`dstName`). `Lowerer.cs:733-737`. Also `n = arg_max(a, b)` names b's value n, where Kusto names the greatest a. Tests: `v-kql.patch`, `01-kql-front-end-lowering.patch`.
10. **A `union` of identities of two domains mints every row in the first domain**: 4 rows made 2 wrongly merged elements. `Lowerer.cs:981-992`. Test: `v-kql.patch`.
11. **Graph patterns.** `(a)-[e]->(a)` matches every edge of the type, not loops only (also in today's text: `engine/src/Sattle.Runtime/Match.cs:150-156`). `-[p*2..2]->` is tested against the shortest distance, so a node also reachable in one step is missed; `cycles=` is ignored. A second `labels(x) has` on one variable replaces the first. `Lowerer.cs:542`, `:581`, `Operators.cs:1176`. Test: `v-kql.patch`.
12. **Names resolve where a function is called, not where it is written.** A `let` read inside a function body is replaced by a column of the calling rows with the same name, and a `let` first used inside a table function takes the function's table parameter of that name and keeps it for every later use. A `let` named like a library function (`rate`, `telemetry`) is replaced by the engine's built-in. `Lowerer.cs:410-426`, `:1023-1030`, `:1074`. Test: `01-kql-front-end-lowering.patch`.
13. **Constants the front end cannot read become nothing.** `now()`, `ago()`, a negative number or a computed value given to a table function, as a fill or in an onCreate/onDelete row becomes null or no fill, a query parameter its default, without a message. `Lowerer.cs:478`. `0x10` and integers beyond 64 bits become 0. Tests: `v-time.patch`, `01-...patch`.
14. **Accepted, then refused in generated text.** Twelve valid texts pass the front end and fail when the printed module is loaded, with a line and column of generated text under the `.sattle` file's name: `summarize` without `by` or without an aggregate, a `datatable` without rows, a negative parameter default, a rule or key name that is no identifier, a quoted column or let name with a dot or space, `arg_max` over text, `strcat` with a number, a `union` of rows that hold elements, a text column as a node id. `engine/src/Sattle.Kql/KqlFiles.cs:50-60`. Test: `02-...patch` (12 rows). Durations below a millisecond are cut off in the same printing (`engine/src/Sattle.Language/Syntax.cs:119`).
15. **Text from an editor throws instead of giving a message**: a `let` named `__s...`, `real(1.5)`, `decimal(1.5)`, `real(nan)`, `1e30`, a leading `.`, `datatable()[]`, a refusal raised while rules are written. The CLI catches only `ArgumentException`. `Lowerer.cs:198`, `:206`, `:214`, `:1001`, `:1092`. A statement that is no step (`services | where ...`, `print 1`) is dropped without a message (`:208`); an unquoted `accept = create, delete` keeps `create` only (`KqlFrontEnd.cs:127`). Tests: `01-...patch`, `v-kql.patch`.
16. **The reports lose lineage under KQL**: the count blocks of `deploymentReport` and `healthReport` name no source elements (2 of 6 and 4 of 12 blocks), with equal graphs. Test: `v-kql.patch`.

### Medium: engine core, merge, fill and time

17. **Windows of 2 h 33 min 43 s or wider drop every row in a replay.** `width * LateHorizonFactor` overflows with the replay's late horizon of 1,000,000 windows; live (3 windows) is not affected. 19. **A telemetry join over two properties loses the windows in which only one has a value.** `Lowerer.cs:919`. Test: `v-time.patch`.
20. **The sink tells 2.5 from 2.50.** Fragments are compared as bytes and a decimal is encoded with its scale, so a retraction written with another scale cancels nothing and the element stays; one input at two chunk sizes ends in two states. Reached through a source retraction, a `distinct` and a join; no shipped definition does it today. `engine/src/Sattle.Runtime/Output.cs:458-464`, `engine/src/Sattle.Core/Graph.cs:121`. Test: `v-sink.patch`.

## Tests that cannot fail or do not run
Shown by mutation: the smallest change of the engine that should make a test fail, run, and reverted.
- **The KQL tests run in no `dotnet test`.** `Sattle.Kql.Tests` and `Sattle.Kql` are not in `engine/Sattle.slnx`, and no README or runsettings names the project or the switch `SATTLE_PROJECTIONS=kql`. A green `dotnet test` from `engine/` says nothing about the KQL front end (`engine/Sattle.slnx:8-12`).
- **The KQL equality tests compare only the end of the estate.** By then the estate's scenarios are over: swapping a threshold's enter and exit counts (`Lowerer.cs:967`) passes 41 of 41; lowering `where time > ago(...)` to nothing (`Lowerer.cs:441`) passes 41 of 41. Swapping `above` and `below` is caught.
- **The rules of an editable view in KQL are tested only through the lens tests under the switch.** Dropping a rule's accept list passes all 46 KQL tests; 16 of 17 `LensTests` catch it, but only with `SATTLE_PROJECTIONS=kql` and the full run.
- **The test of `sattle replay --projections kql` passes when the flag does nothing** (`Program.cs:247`, `KqlProjectionTests.cs:67-78`): KQL and `.sattle` give the same digest on the estate by design.
- **Restart tests pass without a seal.** With the seal restore forced to refuse, the live resume cases, the process-kill cases and the live smoke case still pass; they assert that the host restarted, not that it used the seal. `serve` ignores `--no-seal`, so the process-kill test's "no seal" rows compare a journal replay with a journal replay.
- **Type soundness never checks an element.** Removing a required property from every resolved element passes all six seeds of `TypeSoundnessTests` (`:136-147`): its two sinks always conflict, so no element reaches the assertion.
- **The lens law GetPut never reaches a lens.** It sends edits whose before equals after, which `Edits.cs:114` drops first: a lens that refuses them passes 13 of 13 (the first review's finding, unchanged).
- **With `SATTLE_PROJECTIONS=kql`, 8 `RollupTemporalityTests` cases pass on a projection their edit never reached**: the edit finds its place by a `//` comment, which the printed KQL module no longer has.
- **The known-defect test of the first review's hysteresis defect passes with the fix reverted** (16 of 16); a differential world still catches it (2 cases).
- **Smaller:** the third assertion of `An_observed_call_carries_no_failure...` cannot fail, because the estate has no call that is no dependency (`WorkloadTests.cs:163`); the agreement test of the workload model and the health tree shrank to two Healthy nodes (`HealthTreeTests.cs:369-378`, read); a canvas UI test's pattern accepts Healthy where it asked for a failing state (`canvas/tests/ui/estate.test.tsx:73-82`, read); the editors' replay passes with the core broken in a way that is the same in every notation (`canvas/tests/editors/replay.test.tsx:19`).
- The tests are in `v-tests.patch`.

## Design
Judged against `CLAUDE.md` at the repository root (deep modules, Grokking Simplicity, explicit state machines, every concept counts). Ranked by how much simpler the code would get. Where a point causes a confirmed defect, the defect's number above is named: that is the strongest reason to do it.

### Map/reduce shape: incremental and partitionable by key
The rule: stateless steps are maps, stateful steps are reduces keyed by a declared key, so their state can be split across threads or machines; each step knows which keys, elements and windows a change touches and recomputes nothing else; shared indexes are the cache. Where the committed engine breaks it, read at `4bbf5d4`, most consequential first:
- **Every step runs every operator of a graph.** `Engine.Execute` walks the whole plan of each graph that got input (`Engine.cs:460`); an operator decides by itself whether its input batch is empty. No step knows in advance which keys it touches.
- **Advances scan all keys.** At each frontier advance the Series walks every element it holds, to retract expired windows, refresh fills and move no-data markers (`Output.cs:203-225`, `:311`), whether or not that element has a window ending now. The telemetry store trims each series' oldest windows (`Stores.cs:698`). Work grows with the number of elements, not with the number of windows that close.
- **Traverse recomputes by start, not by key changed.** Each step orders every start, tests each start's reach against the change, and for a changed reach runs a full breadth-first search and retracts and reinserts the whole reach (`Operators.cs:1237-1249`). The health tree's reach to every descendant is the largest state of the estate (the first review measured about 45 KB per tree element).
- **Global state shared across keys.** One engine-wide interner gives every text a number, and compiled plans, operator keys and the seal depend on those numbers (defect 2 comes from this). The identity catalog and its merges re-key elements across every graph (`Output.cs:392-431`, `Engine.cs:329`). The telemetry store is one structure per space. The sink's uniqueness contest compares relationships of one (source, target, type) across the whole graph. `KeyTable` numbers group slots densely and renumbers them on compaction (defect 23). None of this can be split by a step's key without a shared service.
- **One clock and one order.** Windows close, evidence is retained and no data is decided against one logical frontier per space; graphs run in one topological order under one host lock; a merge in one graph re-keys outputs in the same step. Splitting by key needs a watermark per partition and a rule for when a window may close across partitions.
- **Reduces without a real key.** Reports summarise everything into one row (`summarize ... by k = "all"`, the count blocks): a single-key reduce, fine in size but a hot spot by construction.
- **Already keyed and incremental:** Filter, Map and Union are maps; Group, Rollup, Threshold, Distinct and Join keep state per key (group key, join key, element), which partitions naturally; Match works from the changed elements and their adjacency; the sink table is keyed by element. The core layout plan (segments, tables, shared arrangements) is the right base.

What would make the core rebuild meet it:
1. Each stateful operator declares its key (group key, join key, start node, element, (element, property), (source, target, type) for uniqueness), and its state is one `Table` partitioned by a hash of that key. The plan compiler routes a delta to the partitions of its keys and runs only the operators downstream of a touched key.
2. Close windows from a timer queue keyed by window end, so an advance touches only the elements whose windows end in it; no scan of all elements in Series, Rollup, Threshold or the telemetry store.
3. Replace Traverse over a hierarchy by a fold keyed by node (each node's value from its children's, recomputed up the path of a change), as the core layout design already proposes; keep general reachability for the rare case.
4. Make identity independent of a shared counter: ids as content digests (planned in step 6 of the core layout design) and the merge as its own keyed reduce over the identity table, with forwarding as data; then the interner is a per-partition cache, not a source of truth, and plans hold texts, not numbers.
5. A watermark per partition and a minimum over partitions for closing windows; until that exists, partitioning can be by graph (one thread per graph in topological waves), which the current single loop also forbids.
Cost: points 1 and 2 fit into the planned core steps 3 and 4; points 3 and 4 into steps 5 and 6, plus the merge; point 5 is new design and should wait for a measured need. Not estimated in days here.

No input was found on which a KQL text writes another graph than its `.sattle` text.
- **Kusto.Language:** referenced as a package pinned to `[12.4.1]`; no DLL, package or licence file is committed.
- **Core structures:** weights add, zero removes, a negative weight is kept until its insertion arrives; deletion by backward shift without tombstones; slot reuse starts empty; growth re-places every row; segment and bitmap boundaries; hashes use FNV with no per-process seed; the code dictionary compares bytes in full; the segment pool. - **Sink table:** support counts, a retraction before its insertion, the same fragment from two sinks, resolution independent of row order, `Flush` order not reaching a commit (patches sort their edits), merge remapping, `emit update` without a create, and the seal content of format 3 (written field by field; a snapshot shares no array with the live engine).
